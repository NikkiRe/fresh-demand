# Спрос и управление запасами

## Задача

Проект проверяет, когда стоит увеличить заказ, чтобы лучше оценить скрытый
спрос. Если товар закончился, продажи ограничены запасом: система видит
`sales = min(D, Q)` и признак `sold_out = (D >= Q)`, где D — спрос, Q — заказ.
Равенство считается цензурированием. Проданные восемь единиц при заказе восемь
совместимы и со спросом восемь, и со спросом тридцать.

Издержки заказа равны

```
cu · max(D − Q, 0) + co · max(Q − D, 0).
```

Здесь cu — стоимость недозаказа, co — стоимость излишка. При известном
распределении оптимален квантиль уровня `cu / (cu + co)`. В эксперименте
проверяется, помогает ли дополнительный запас выяснить именно ту часть
распределения, от которой зависит этот заказ.

## Почему больше наблюдений может не помочь

В [контрольном примере](reproduction.md) половина спроса равна пяти. В одном
распределении оставшаяся половина равна двенадцати, в другом — тридцати пяти.
При заказе восемь наблюдения в обоих случаях имеют одинаковое распределение:
пять продаж без исчерпания запаса либо восемь продаж с исчерпанием. Количество
таких наблюдений не позволяет различить хвосты.

При стоимости недозаказа и излишка 1:3 оптимальный заказ в обоих случаях
равен пяти. При 3:1 оптимальные заказы различаются: двенадцать и тридцать пять.
Один и тот же недостаток данных может мешать решению при одних стоимостях и
не мешать при других.

## Реализация

Для функции распределения `F(d) = P(D <= d)` используются наблюдения с
`Q > d`. Такой заказ позволяет проверить событие `D <= d` при любом исходе.
Частоты считаются отдельно по порогам; их монотонность восстанавливается
изотонической регрессией. Для неизученного хвоста явно задаётся предположение
о распределении оставшейся вероятности.

Доверительные границы строятся через неравенство Хёффдинга. Они требуют
стационарного независимого спроса внутри каждой фиксированной группы и
заказа, выбранного до текущего спроса. Границы учитывают весь заявленный
горизонт наблюдений. При смене распределения эти условия нарушаются.

Для каждого допустимого распределения сравниваются ожидаемые издержки выбранного
заказа и оптимального заказа при том же распределении. Их разница — regret.
Решатель минимизирует наибольший regret по всем распределениям внутри
доверительных границ. Расчёт за O(M), где
M — максимальный спрос, относится
**к одной задаче по фиксированным границам функции распределения**. Решатель
проверен отдельными линейными программами. [Доказательство](identification.md)
описывает эту постановку; полный анализ
[Kumar–Mouchtaki](https://arxiv.org/abs/2602.16842) в проекте не воспроизводится.

Для дополнительного запаса сравниваются три правила: равномерное распределение,
уменьшение общей неопределённости спроса и уменьшение неопределённости заказа.
Бюджет распределяется динамическим программированием. Прогноз полезности
информации использует рабочее распределение и ожидаемые счётчики будущих
наблюдений. Это приближение: нелинейный расчёт по средним счётчикам отличается
от усреднения результатов по всем будущим наборам данных.

Отдельные методы могут оставить часть бюджета неиспользованной, если
ожидаемая польза не покрывает стоимость лишнего запаса. Для сравнения есть
Kaplan–Meier, геометрическая модель с байесовским обновлением и LightGBM.

## Проверка и результаты

В [протоколе](experimental_protocol.md) заранее выбраны основной сценарий и
сравнение с равномерным распределением. Настройка использует прогоны 0–3,
проверка — отдельные прогоны 1000–1029. Сравниваются 16 стратегий в шести
сценариях. В проверочном прогоне 400 раундов и четыре группы спроса. Основные
стратегии используют одинаковые восемь дополнительных единиц за раунд, если
позволяет вместимость; стоимость недозаказа и излишка учитывается полностью.
Общая история до начала эксперимента исключается из затрат одинаково.

Ожидаемый regret — разность ожидаемых издержек выбранного заказа и оптимального
заказа при известном распределении. Эталон использует тот же набор действий
и не знает следующую реализацию спроса. Стратегии получают одинаковые случайные
траектории, каждая видит только собственные наблюдения. Парный bootstrap
пересэмплирует целые независимые прогоны.

**Преимущество основного метода не установлено:** разность с равномерным
распределением равна +0,91 с 95% интервалом [−58,26; 59,81]. Это также не
доказывает равенство методов. На других сценариях результаты расходятся:
метод лучше равномерного распределения при длинном хвосте и в среде по данным
ритейла, хуже — на геометрическом спросе и после смены режима.

Метод, учитывающий стоимость исследования, может расходовать меньше запаса и
иногда даёт меньшие издержки. Его результат показан отдельно. Проверка на новых
прогонах сравнивает его также с правилом, которое экономит запас без оценки будущей
информации; преимущество сохраняется не во всех сценариях. Вторичные интервалы
не скорректированы на множественные сравнения. Числа и все сравнения находятся
в [отчёте](research_report.md).

## Что означают результаты на FreshRetailNet

Из обучающих данных выбраны 10 000 пар «магазин — товар». Первые 28 дней
использованы для группировки, первые 69 — для распределений продаж на днях
полного наличия. Официальная проверочная часть не использовалась. Затем
симулятор независимо генерирует спрос из этих распределений; он не повторяет
реальную историю поставок.

Дни полного наличия могут отличаться от дней дефицита. В данных нет необходимых
исторических объёмов заказа и правил их назначения, поэтому истинный спрос
при отсутствии товара не установлен. Запас, частоты групп, издержки и смена
режима заданы экспериментом. Полученные затраты выражены в условных единицах;
они не доказывают прибыль или снижение списаний настоящего ритейлера.
